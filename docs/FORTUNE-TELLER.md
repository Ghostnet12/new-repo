# The Fortune Teller

Added September 9, 2026 at `/fortune-teller`, linked from the main navigation, menu and footer. The normal reading hero is omitted on this route so the activity appears directly below navigation.

- Original fictional mechanical-teller artwork generated for The Fold; optimized to a 1024 × 1536 WebP (287 KB). No film logos, actor likenesses or copied fortune text.
- 2,032 original fortune messages: the initial 32 plus 2,000 individually written additions in 40 themed chapters. Titles and complete messages are unique after case/punctuation normalization. The collection is authored text, not interchangeable sentence combinations or a live AI service.
- A Fisher–Yates shuffle deals the entire collection before reshuffling, with no immediate repeat across collections. Remaining card IDs and the last card are saved in local storage after each draw. Progress survives navigation and refresh in the same browser when storage is available; a second tab observes completed draws on its next draw. Simultaneous tabs are not an atomic shared queue. Clearing browser data or using another browser starts a separate collection. Invalid or obsolete stored collections restart safely; blocked storage retains the sequence in memory for the open page.
- Chapter keys and the order of lines within each chapter form stable card IDs; preserve them when editing existing text. Adding/removing cards changes the collection size and intentionally starts a fresh shuffle. The Fortune Teller route loads separately so the expanded corpus is not added to the initial tarot page bundle.
- Each draw includes a random number from 1–99 and its issue date. This is explicitly a playful reflection, not a prediction.
- A 4.8-second, three-stage performance (awakening, listening, inscription), followed by a stationary fortune card. The waiting area has no floating card or orbit animation. Pending stages are cancelled on navigation. Reduced-motion visitors receive an immediate card without animation.
- The teller has a matching lighting variant with bright ruby-red eyes and a stronger violet ball glow; the lighting effect activates only while a card is being made. Both the initial state and completed-card state return to the subdued original artwork. Layered images preserve alignment across screen sizes. Gold/plum celestial artwork frames both the on-page card and its download.
- Keepsake cards export locally to 1000 × 1500 PNG. The ornate frame loads from the same origin and is cached; text is measured to fit the clean parchment area. Blob URLs are revoked on replacement/unmount. A failed image preparation offers a retry. Downloads follow the visitor's browser's normal download behavior.
- The first revealed card displays that same generated PNG used by the image preview, native sharing, and download, at its natural 2:3 proportions. The decorative frame is no longer stretched with CSS border-image. An equally proportioned placeholder reserves space until the image is ready; accessible fortune text remains in the page. If image creation fails, readable text and a retry button remain available.
- On iPhone/iPad, **Save to Photos** opens the native sharing sheet when PNG file sharing is supported, with instructions to choose Save Image. Other devices get **Save or share card**, or an image preview when file sharing is unavailable. The PNG File is prepared before the tap so sharing retains user activation; only the image is sent. The website cannot choose the destination or confirm that Photos saved it.
- **View card image** always provides a real PNG image for touch-and-hold saving, and **Download PNG** remains an explicit alternative. Unsupported or blocked sharing opens that preview. Cancelling the native sheet does not trigger a download. Pending share actions are guarded against double taps and navigation.
- No new service, credentials, payment requirement or server endpoint. No user questions or personal details are collected. Existing ambient music stays mounted during page navigation.

Validation: `node --test client/test/fortunes.test.js client/test/fortuneReveal.test.js` covers full-deck exhaustion, repeated reshuffles, refresh persistence, saved order, sequential tabs, corrupt storage and failed writes. Corpus checks require exactly 2,032 unique IDs, titles and messages. The production client build and live HTTP/asset checks verify delivery. Native Canvas checks measure every keepsake layout against the parchment bounds; the frame and shared PNG export preserve the existing 2:3 proportions. Browser interaction and physical-device Photos saving are not verified by these checks.

Photo-saving update: `node --test client/test/fortuneShare.test.js` checks immediate PNG sharing, unsupported/blocked sharing fallbacks, and cancellation behavior. Physical-device Photos saving still requires device verification; the native sharing menu belongs to the device.

## Yes / No mode — September 9, 2026

- An accessible gold toggle switches between the original fortune collection and a separate deck of 2,032 individually written cheeky answers (1,016 yes and 1,016 no). Visitors hold a question in mind; nothing is typed, sent to a provider, or stored about their question. No deck count appears in the interface.
- Answer IDs use stable chapter keys and authored line numbers in `yesNoChapters.js`. The complete messages are authored lines, not assembled sentence combinations. Repeated verdict headings distinguish yes from no; all complete message texts are unique.
- Each mode uses the same Fisher–Yates draw logic with its own storage key. The original key and saved queue are preserved. The new key is `the-fold-yes-no-deck-v1`. Every card in a mode is dealt before that mode reshuffles, with no immediate repeat at the cycle boundary. Browser-storage limits and sequential-tab behavior remain as described above.
- Switching modes does not draw a card and retains the current card from each mode while the page stays open. The mode switch is disabled during the reveal sequence. The original subdued artwork, temporary glowing eyes and ball, 4.8-second reveal, reduced-motion behavior, and stationary card remain.
- Answer keepsakes use the same 1000 × 1500 frame and shared PNG, with “The teller’s verdict” above the answer. Native sharing, image preview and explicit download remain available. The original card label is unchanged.
- `client/test/yesNoFortunes.test.js` checks exact content counts and uniqueness, stable line IDs, independent queues and refreshes, repeated complete cycles, corrupt or crossed snapshots, blocked storage, failed writes, device selection and export labels. These are source, logic and layout checks, not a claim of physical-device Photos or browser interaction verification.

Release validation: all 27 checks in `yesNoFortunes.test.js`, `fortunes.test.js`, `fortuneReveal.test.js` and `fortuneShare.test.js` pass. The client production build passes; the additional corpus remains in the lazy Fortune Teller page bundle.
